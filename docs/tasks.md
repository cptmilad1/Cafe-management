# وضعیت کار: دیتابیس کافه

- بر اساس `docs/ai.md` یک اسکلت PostgreSQL برای مدیریت کافه اضافه شد؛ موجودیت‌ها به‌دلیل نبود نیازمندی جزئی در متن، مدل پایه هستند.
- اتصال مشترک `pg.Pool` در `database/base/pool.js` قرار دارد و تنظیمات محیطی را از `.env` می‌خواند.
- فایل‌های مستقل در `database/schema/` جدول‌های کاربران، دسته‌بندی‌ها، محصولات، میزها، سفارش‌ها، آیتم‌های سفارش، پرداخت‌ها و ایندکس‌ها را می‌سازند.
- `database/schema/run.js` فایل‌های SQL را به ترتیب شماره و در یک تراکنش اجرا می‌کند. اجرای آن با `npm run db:schema` انجام می‌شود.
- وابستگی‌های ریشه `pg` و `dotenv` نصب شده‌اند؛ متغیرهای نمونه در `.env.example` هستند. مقادیر واقعی اتصال باید در `.env` تنظیم شوند.
- بررسی syntax جاوااسکریپت و نصب وابستگی‌ها موفق بود. اعمال schema هنوز تأیید نشده: اجرای runner با `ECONNREFUSED` روی `localhost:5432` شکست خورد، چون PostgreSQL در دسترس نبود.
- گام بعد: PostgreSQL را اجرا کنید، دیتابیس `cafe_management` را بسازید، تنظیمات `PGHOST`، `PGPORT`، `PGDATABASE`، `PGUSER` و `PGPASSWORD` را در `.env` قرار دهید و `npm run db:schema` را دوباره اجرا کنید.

## بک‌اند

- بک‌اند Express در `backend/` با middlewareهای Helmet، CORS و JSON، بررسی سلامت `/api/health` و پشتیبانی Socket.IO ساخته شد.
- با `forEach` مسیرهای CRUD برای کاربران، دسته‌بندی‌ها، محصولات، میزها، سفارش‌ها، آیتم‌های سفارش و پرداخت‌ها ثبت می‌شوند؛ controllerهای GET، GET by ID، POST، PUT و DELETE از factory مشترک می‌آیند.
- ورودی‌ها با Zod اعتبارسنجی می‌شوند؛ queryها پارامتری‌اند، خطاهای اعتبارسنجی/قید دیتابیس پاسخ استاندارد دارند و رویدادهای CRUD از Socket.IO احراز هویت‌شده منتشر می‌شوند.
- رمز کاربران پیش از ذخیره با bcrypt هش می‌شود و ستون `password_hash` در پاسخ‌های API قرار نمی‌گیرد. مسیرهای CRUD نیازمند Bearer JWT هستند؛ ورود در `/api/auth/login` و ساخت ادمین اولیه (فقط وقتی جدول کاربران خالی است) در `/api/auth/bootstrap` انجام می‌شود.
- متغیرهای `PORT`، `CORS_ORIGIN` و `JWT_SECRET` به `.env.example` افزوده شدند؛ یک مقدار تصادفی حداقل ۳۲ کاراکتری برای `JWT_SECRET` تنظیم کنید. اجرا با `npm start` یا توسعه با `npm run dev` است.
- دسترسی CRUD با JWT کنترل می‌شود و مدیریت کاربران فقط برای ادمین مجاز است. تست‌ها با `npm test` پاس شدند و `npm audit --omit=dev` بدون آسیب‌پذیری گزارش شد؛ برای کارکرد API باید PostgreSQL مطابق بخش دیتابیس بالا فعال و تنظیم شده باشد.
